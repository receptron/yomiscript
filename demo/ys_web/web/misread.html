仕組み

  1. 読み手（Yomite） 文章を書いた LLM が、その文脈で読みを決めます。 一日から三日まで休みです。
  2. YomiScript 発音（IPA）と元の文字を書いた、エンジンに依存しない形式です。 ja /tsɯitatɕi<t:一日> kaɾa<t:から> mikka<t:三日> made<t:まで> jasɯmi<t:休み> desɯ<t:です。> ↘/
  3. 語り手（Katarite） 読みを推測せず、書かれた通りに音声にします。文章の解析が要らないので軽量です。 Kokoro-82M / Supertonic 3

「一日」を「ついたち」と読むと決めたのは LLM で、エンジンはそれに従うだけです。読み手と語り手は別々に置き換えられます。日本語では、話す直前に辞書とピッチモデルがアクセントを加えられます。

この仕組みで動くデモ

青空朗読文庫 『注文の多い料理店』全234文を朗読します。あらかじめ用意するのは LLM が書いた 75 KB の YomiScript だけで、アクセントと音声はブラウザーが文ごとに作ります。 駅のアナウンス 列車と時刻から案内を作ります。ここでは LLM ではなく文型の規則が YomiScript を書いています。読み手は置き換えられるという例です。

使ってみる

コマンドライン

npm install -g yomiscript
yomiscript speak "ja /ame<t:雨> desɯ<t:です。> ↘/"
yomiscript instructions   # LLM に渡す、YomiScript の書き方

MCP サーバー（Claude Code など）

claude mcp add yomiscript -- npx -y @yomiscript/mcp

ブラウザーやアプリから使うパッケージは @yomiscript/kokoro と @yomiscript/ja-accent です。モデルは初回の利用時にダウンロードします。詳しくは パッケージの一覧をご覧ください。

目指していること

音声合成エンジンごとに発音の指定方法が違う状態をやめて、LLM とエンジンの間に共通の形式を置くことを提案しています。YomiScript は IPA と BCP 47 の言語タグに基づく言語非依存の仕様で、アクセント、声調、強勢、言語の切り替えまで同じ形式で書けます。仕様は公開していて、現在は v0.2 のドラフトです。

SSML にも発音を指定する仕組みがありますが、文字が本体で、発音は省略できる補足です。YomiScript では発音が本体なので、エンジンは文字を読む必要がありません。YomiScript の狙いは読みの精度だけでなく、言語に依存せず韻律まで書けることです。

他の言語についての研究はこれからですが、省略形などの読み方に有効だと考えています。

このように分離しておくことで、語り手（Katarite）の部分だけに集中した、オープンな形での研究・開発が進むことを期待しています。
